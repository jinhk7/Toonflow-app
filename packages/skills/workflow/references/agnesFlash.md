# Agnes Video 2.5 Flash 制作规则

仅用于 workflow 入口已选 Agnes Video 2.5 Flash 的任务。这里维护 Agnes 的拆分、参考、提示词与检查策略；Seedance PART A 的 15/30 秒、A9 模板、分段优化和路由锁不适用于本分支。

## 1. 恢复选择与剧情事实

沿用本项目已确认模型，标准 ID 为 `agnes-video-2.5-flash`。用户只说“Agnes”且没有其他 Agnes 型号选择时使用本分支；只说“2.5”时依据已确认家族解释，不能把 Agnes 2.5 Flash 当 Seedance 2.5。实际 Provider 和完整 ID 从当前配置核验，缺接入时完成文字规划并准确报告缺项。

读取指定原文、最新修改、已采用资产和制作记录。事实优先级：用户最新明确修改→原文/定稿剧本→用户资产设定→AI 草稿。保留全部剧情、动作、声音、执行者、对象与先后关系；不为连贯补开盖、取出、起身等原文没有的事件，不把 AI 曾添加的细节当事实。不添加未要求的对白、旁白、字幕或音乐；原有环境声与动作声保留。未知身份保持原有抽象层级。

先列源事件编号和完整覆盖关系，再细化当前批次。分批不删后续剧情。不能同时满足总时长与完整剧情时说明矛盾并提出可确认调整，不偷偷删动作或加速对白。内容审阅与实际生成授权分别判断，沿用已批准范围。

## 2. 逐镜规划与时长

每个导演镜头记录：镜号、源事件、叙事目的、`start_state`、`action`、`end_state`、空间关系、镜头/运镜、准确声音、引用职责、`duration_seconds`、`duration_reason`。保留导演镜头到实际生成单元的对应关系。

- 按动作、对白语速、反应、运镜和必要停留选择 **4–12 秒整数时长**；不固定 8 秒，不平均分配总时长，也不刻意让每镜时长不同。
- 超出 12 秒的动作在合理动作/语义边界拆成多个单元，保留完整因果与状态交接；不能把 15/30 秒 Seedance 提示词只改模型名后提交。
- 简短片段可与相邻合理内容合并，或保留有意义的停留；不能填入无源动作凑时长。规划总时长、实际生成时长、最终保留时长分别记录。
- 涉及节奏、动作顺序、生成单元数量或替代拍法变化时，展示旧/新方案与理由供确认；已批准方案内的具体化不逐工具重复问。
- 每单元只安排能看清的动作链和可实现的摄影机运动。需要降低复杂度时优先拆分、调整构图或运镜，不删除关键动作。需要切镜必须有明确意图，默认不把多个空间/复杂事件塞进一个短请求。

输出至少包括全片事件覆盖表、逐镜卡片、单元时长与拆分理由、素材缺项、正式提示词及待确认变化。结构字段用于记录，只有视频描述进入 prompt，不把审批、清单和多个镜头正文一并发送。

## 3. 按镜头选模式和素材

规划依据为 [官方 Flash 文档](https://www.agnes-ai.com/zh-Hans/docs/agnes-video-25-flash)，核验日期 2026-09-26；提交仍须核对 Toonflow 实际 Provider 能力与字段映射，不能以技能添加成功推断接入可用。

| 模式语义 | 适用场景与素材规则 |
|---|---|
| text | 无媒体的纯文本请求，不带首尾帧、图片、音频或视频参考 |
| keyframe | 精确控制人物位置、持物或起始姿态时优先首帧；首帧、尾帧至少一个，不能同时带参考 images/audios/videos。尾帧仅在剧情需要且当前接口支持时使用，不强制双帧 |
| reference | 需要多素材或声音参考时考虑；images ≤5、audios ≤3，至少一类非空；不带首尾帧，不支持视频参考；参考图不保证锁死起始构图 |

Flash 输出档位为 720P，生成时长 4–12 秒，单请求 n=1。实际像素、画幅与声音能力须读配置并检查真实输出；不要承诺精确口型或跨镜头固定音色。图片生成的尺寸与视频分辨率分别设置。

向用户说明每镜选择理由与取舍。用户同时要求精确首帧和声音参考时，说明模式冲突，提出首帧配文字声音描述、reference 接受构图自由度，或另行后期声音方案；由用户选择，不静默丢掉任何素材。原文没有人声就不为使用参考能力强制生成声音样本。

资产图锁身份、环境、道具外观；动作首帧锁该镜零时刻。可以先用多张资产图通过已配置生图模型合成首帧，再仅将合成首帧交给视频模型。已有适用资产直接复用，只补当前镜头缺的状态版本，不要求先生成全部资产。必要时读取 [资产制作](assets.md)，其中 Seedance 专属限制只用于 Seedance。

## 4. 实际首帧与状态衔接

首帧提示词只写静态可见事实：画面左右、主体朝向、四肢/嘴部姿态、持物、物体间隙和空间关系。“准备/即将”不能代替姿态。

实际打开对应版本的图，检查身份、人数、道具、外观状态、环境和动作空间。首帧已经是动作终态时先修图；例如计划“从树旁起身”，图中已经站立，不能靠视频文字让它暗中坐回去。无法看图时标为未核验，由用户采用后再推进依赖它的生成。

相邻单元有连续时空关系时，比较位置、朝向、运动方向、持物、动作进度、服装/污迹、道具数量和环境。计划末态用于规划，实际采用视频末态/真实交界帧或明确用户反馈用于后段制作；不把计划冒充结果。无连续关系的镜头不强锁同一站位。当前结果穿帮先处理当前结果，不把错误写成新剧情。

## 5. 提示词与引用映射

每单元生成提示词依次交代：实际起点→按原文顺序可见的动作→终态和必要停留→摄影机→准确声音→必要的连续性约束。约束具体且少量，避免堆形容词。keyframe 从真实图的姿态展开，不描述相反起点；reference 明确每份素材负责身份、环境、道具或声音，不把多视图当多个角色。

可用以下字段组织审核稿，最终 prompt 不包含未填占位内容：

```text
单元 / 源事件 / 导演镜头 / 版本：
模式与理由 / 时长与理由：
实际素材、版本、用途与引用顺序：
起点：
动作过程：
终态：
景别、构图与运镜：
声音（原文对白、说话者、环境声及时间要求）：
必须保持的状态与空间关系：
```

语言沿用用户选择；使用英文生成提示词时，提供同镜号、同用途、同版本的完整中文审核文本，中文不作为第二份生成输入。英文中的原文中文对白保持原句。用户要求全中文时可直接使用中文，不额外强制翻译。

Agnes 原生 reference 使用 `<Picture N>` / `<Audio N>`，图片与音频分别编号；Toonflow 可能使用统一的 `{{ref N}}`，以实时 Provider 转换为准。生成前建立“节点/端口→实际文件→类型与顺序→上游引用标记”映射，检查最终展开文本。不能盲目混用两套标记、把统一 ref 2 当 Audio 2，或引用不存在的素材。无法确认转换时暂停该提交并指出具体缺项，不通过改写标题假装完成绑定。

使用 [画布执行](canvasExecution.md) 的实时节点方法写 prompt；不要用 STRING 连线重复追加完整剧本。Agnes 原生 seconds/size/aspect_ratio 与 Toonflow duration/resolution/ratio 的对应由 Provider 负责，不把原生 HTTP 字段直接塞入未知节点 schema。媒体走现有上传转换，不能把 localhost、blob 或本地文件路径当上游可访问 URL；已有 R2 后端直接复用，不在技能里写入凭据。

## 6. 提交、等待与修订

提交前完成事件覆盖、时长、真实首帧、参考映射、参数和声音检查；列出尚未通过项。保存实际完整 prompt、素材版本/顺序、模型、参数、workflow 版本、批准范围与尝试标识，回读节点与已确认方案一致后生成。更改节点文字不会改变已提交任务，旧请求快照保留。

沿用历史制作限制：图片同时在途 ≤5、视频 ≤3，当前更低限制优先。依赖前图或前片采用结果的任务顺序推进；运行中和提交结果未知都占名额。先验证代表镜再推进已批准批次。

生图 300 秒是分段检查窗口，单次等待 ≤60 秒，只有真实工具支持时才能等待/查询；不能用技能提高宿主硬超时。保存实际返回的任务标识，超时查询原任务，不能重新生成充当查询。没有查询能力时登记 unknown、保留输出与恢复入口，说明需用户回报或恢复连接，不伪造后台执行。当前 Toonflow 关闭网页可能中止本地处理，本技能不承诺修复该运行机制。

失败先定位参考、起点、动作复杂度、空间、声音或参数问题，提出最小修订和受影响镜头；保留旧成果，新增尝试是否需再次授权取决于已有批准范围，不能无限重做。

## 7. 审片与交付

实际可读媒体优先检查动作缺失/错误、前后状态冲突、空间关系错误。每项记录“通过 / 发现问题 / 无法判断”，附实际媒体版本、时间范围及证据。可抽帧时按镜号和时间生成联系表并查看，异常处加密；抽帧不能证明全程动作、音轨或口型通过。

生成成功、文件可读、视觉、动作、连续性、对白、音色、口型和实际播放分开记录。无法听音时写待听审；人类采用与 AI 检查分开。不得将素材路径或生成状态当完成审片。

按 [状态与交付](stateAndDelivery.md)保存候选与采用版本。用户要求整片且实际工具支持时，按采用片段顺序与确认入出点拼接，保留完整因果与对白，检查成片切点、解码和播放；只生成了分段时如实交付分段及缺项。

## 依据与迁移边界
